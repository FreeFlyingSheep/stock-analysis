# Frontend (SvelteKit)

[English](05-frontend-sveltekit.md) | [中文](05-frontend-sveltekit.zh-CN.md)

## Technology Overview

- Vibe coding workflow, mainly co-generated by Claude Opus 4.5, GPT-5.1-Codex-Max, and GPT-5.
- SvelteKit 2 + Svelte 5 + TypeScript + Vite.
- Frontend proxies backend through `/api`; dev target is configurable in `vite.config.ts`.
- Production uses Nginx reverse proxy for a unified domain.
- Production serving mode uses Node runtime.

## Implementation Details

### Pages and Functional Structure

Main routes:

- `/stocks`: stock list and filtering
- `/stocks/[code]`: stock detail
- `/chat`: chat page

Main modules:

- `src/lib/api.ts`: backend API and SSE wrapper
- `src/lib/chatHistory.ts`: local chat history management
- `src/lib/components/*`: chat/table/floating widget components

### Streaming Chat Consumption

`streamChatMessage` handles:

- call `POST /chat/start`
- connect SSE stream
- process `token/done/error/ping` events
- reconnect with exponential backoff (up to 10 attempts)

### Internationalization

`i18n.ts` provides English/Chinese switching.

## Current Potential Issues

- Chat history depends on local storage, limiting cross-device consistency.
- Frontend API error classification is still generic and lacks observable error-code mapping.
- SSE reconnect/replay exists for weak networks, but end-to-end stress benchmarks are missing.

## Improvement Directions

- Add server-side session sync strategy (by user account or anonymous token).
- Build a unified frontend error model (business code, retryability, UX prompt strategy).
- Add frontend chain metrics (SSE success rate, reconnect count, first-token latency).
- Introduce contract tests to automatically detect API schema drift.
